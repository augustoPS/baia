# CLAUDE.md

> Tracked on purpose. Agents work on baia from two places: this repository, and a
> git worktree under `~/Projects/.worktrees/baia--<item>`. A worktree is a full
> checkout, so a tracked file reaches it; the workspace rules at
> `~/Projects/.claude/rules/` do not, because they are scoped to `baia/**`. Rules
> that only ever apply to this repository live here rather than there.

## What this is

A macOS terminal workspace in Swift and AppKit, generated by XcodeGen, embedding
Ghostty's terminal engine through `Lakr233/libghostty-spm`. Twelve local packages
under `Packages/` hold everything decidable without a window; `Sources/` is the
app target and holds what needs AppKit. Full context, decisions and open threads
are in the vault hub at `~/Projects/vault/projects/baia/baia.md`. Read it before
starting anything larger than a single fix.

## Build and test

| command | what it does |
|---|---|
| `make build` | Debug build. Errors only on stdout, full log at `.build/xcodebuild.log` |
| `make test` | Every local package's tests. No app build, no signing, no Metal |
| `make gen` | Regenerate `baia.xcodeproj` from `project.yml` |
| `make run` | Build Debug and launch `baia-dev.app` detached |
| `make install` | Build Release and install `baia.app` to `/Applications` |

Never bare `xcodebuild`. Measured cold in a fresh worktree: `make build` about 25
seconds, the first `make test` about 95 across twelve suites, every `make test`
after that about 8. A command that looks stuck is usually building.

`make test` never compiles `Sources/`, so it cannot see a call site you broke.
`make build` never runs a test, so it cannot see behaviour you changed. Work that
touches a package the app target imports needs both.

## Two builds, and they do not share state

Release is `baia.app`, bundle id `pasqualotto.baia`, installed in `/Applications`
and used daily. Debug is `baia-dev.app`, bundle id `pasqualotto.baia.dev`, built
by `make run` to test the next change. They are meant to run at the same time.

That only works because each owns a directory under Application Support, named by
`BAIA_SUPPORT_DIRECTORY` per configuration in `project.yml` and read back through
`BAIASupportDirectory` in `Info.plist` by `Sources/SupportDirectory.swift`. It
holds `session.json`, `control.sock` and `recent-projects.tsv`. Sharing them
breaks three ways: the second instance to launch finds the socket bound and runs
**with no channel at all**, so `baia` inside its panes fails; `session.json` has
one writer and the loser's windows are gone; and one bundle id for two apps leaves
`open -b` picking whichever LaunchServices registered last.

Settings are deliberately shared. Both read `~/.config/baia/config.json`, because
testing a build against settings that are not the ones in daily use tests the
wrong thing.

Anything matching a bundle path must accept both names. `baia-dev.app` does not
contain the substring `baia.app`, and the rename silently opened a hole in
`guard-baia-alive.sh` that every existing check passed.

## Non-negotiables

- `project.yml` is the only build source of truth; `baia.xcodeproj` is generated
  and gitignored. Never edit a pbxproj, never add files through Xcode.
- Never add `info:` or `entitlements:` keys to the target in `project.yml`.
  XcodeGen treats those as files it owns and silently overwrites `Info.plist` and
  `baia.entitlements` with stubs on every `make gen`. They are wired through
  `INFOPLIST_FILE` and `CODE_SIGN_ENTITLEMENTS` instead.
- kero (`egoist/kero`) is GPLv3. Read it for design, never copy its Swift in.
  Depend on upstream `Lakr233/libghostty-spm` (MIT), not
  `egoist-labs/libghostty-spm`.
- Terminal surfaces use `backend: .exec`. `.inMemory` is an emulated sandbox shell
  that cannot run git or an agent, and it is what the upstream example ships with.
- Never relax the OSC 52 clipboard denials in `TerminalPaneController`.
  Terminal-driven clipboard reads let remote output exfiltrate the host clipboard
  through the PTY.

## Where logic belongs

Anything answerable without a descriptor or an `NSWindow` belongs in a package,
and the app target keeps only what genuinely needs AppKit. This is not a
preference. Five rules were found living in `Sources/` across v1.1, and three of
the five were wrong or unenforced when they moved to a package, because the app
target has no test target and nothing could reach them.

A function that moves out of a file leaves a call site behind, so a move that
compiles is the smallest honest unit. Commit each green step separately.

## Diagnostics

Every test script and probe goes in `Diagnostics/<name>/` with a `run.sh` that
works from any working directory, a README naming the question it answers, and the
probe itself. Shared harness (a real-CGEvent clicker, a dependency-free PNG pixel
reader, the git-marker-state fixture builder, the capture driver) is in
`Diagnostics/lib/`; reach for it before writing another one.

Package tests answer anything decidable without an `NSWindow` or a descriptor. A
probe is for what needs a real window, surface, shell, socket, or human eye.

**Never run a `Diagnostics/*/run.sh`, `make run`, or `make run-attached` from
inside a baia pane.** You are running inside the app they launch or restart.

## design/

`design/` is the Claude Design conversation and holds no tooling. Its two traffic
folders split by direction, not topic: `inbox/` is design to code (passes and
critiques coming back), `handoffs/` is code to design (the brief and the captures
going out). A single design pass lands in both. Both are gitignored, so nothing
worth keeping may live in them; the durable copy of a brief goes in the vault.

`design/vitreous/` is the exception: tracked, and maintained like source alongside
the Liquid Glass work it governs, updated in the same commit as the code that
adopts a treatment. It carries its own `CLAUDE.md`. Captures regenerate via
`./Diagnostics/lib/capture.sh [output-dir]`.
