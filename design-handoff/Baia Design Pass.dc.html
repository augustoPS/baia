Pick the ANSI slot whose meaning matches — 1 alert, 2 ok, 3 warn, 4 info — then blend it toward background until it stops shouting, then hand it to readable. Never write a hex. A theme with a pastel ANSI table gets pastel chrome for free; a theme with a neon one gets neon chrome, which is correct, because that is what its terminal looks like.

Nothing here branches on isDark except the repair chain, which already does. On a light theme bar darkens instead of lifting, because it blends toward foreground and foreground is the dark end there. The scrim in option C is background at 0.28, so it lightens a light pane and darkens a dark one — recession either way.

03

Attention — two levels, not one

You asked for three things that look contradictory: urgent across four panes, tolerable while it waits, settled once acknowledged. They are only contradictory if attention is one state. Split it. Level 2 is unacknowledged and loud. Level 1 is acknowledged and still waiting, and it is quiet. Focus or a keystroke moves 2 → 1. The agent no longer asking moves 1 → 0.

DRAWN >_ · THE GAP IS A NUMBER

A two-segment polyline and a rectangle. No font in the export, no metrics to argue with, and the one relationship that matters — how far the cursor sits from the chevron — is a constant you can move. Chevron and cursor share a stroke weight of 56 and a baseline at y=658, so they read as one unit rather than two marks. Three gaps below, each at 120px and 16px.

GAP 32

Tight. The two shapes bond into one glyph, which is what you want at 16px and slightly cramped at 1024 — the chevron's point almost touches the bar.

GAP 64 ✳

One stroke weight plus a little. Reads as prompt-then-cursor, the two shapes still one thought, and it is the only gap that survives both 1024 and 16 without changing character.

GAP 112

Loose. At 1024 it reads as a waiting prompt with room to type into, which is a nice idea and a bad icon — at 16px the two pieces separate and the mark loses its centre.

08

Making it settable — config keys, not a control panel

Shipping every option is a way of not deciding, and it costs more than it looks: three focus treatments × four accents × two attention levels is twenty-four screens nobody tests, and some of those combinations are actively wrong. Invert plus loud fills the bar for two different reasons at once — pick both and the app can no longer tell you the difference between "here" and "help".

So: settings for the ones that are genuinely preference and coherent alone, one shipped answer for the rest. Four keys, not twenty-four screens.

A theme file that lets you set focus-color = #ff0000 breaks the standing rule this whole system is built on: chrome matches the terminal theme and never the reverse. The moment a hex is user-settable, switching ghostty themes leaves the chrome behind, and every contrast guarantee in §01 is void.

The setting is therefore a named derivation, never a colour: accent, bone, ansi5, ansi6. You choose which relationship to the theme you want; the theme still decides what that resolves to, and readable() still has the last word.
FOUR KEYS · ~/.config/baia/config.json

This surface already exists. BaiaSettings owns a JSON file at ~/.config/baia/config.json with camelCase keys, seventeen of them, and it already carries every value quoted in §02 — fontSize 11.5, backgroundHex #141414, backgroundOpacity 0.85, transparentTitlebar true. Four more keys, in the spellings that file already uses:

"focusStyle":     "recede",   // recede | invert | frame
"focusAccent":    "accent",   // accent | bone | ansi5 | ansi6 — a name, never a hex
"attentionStyle": "loud",     // loud | quiet
"unfocusedScrim": 0.28        // Limits.scrim = 0 ... 0.34
Settings.swift
four stored properties, values in defaultSettings, and Limits.scrim beside the existing ranges
no public init — callers mutate defaultSettings; keep it that way
FocusStyle.swift
three enums shaped like CursorStyle — String, Sendable, Equatable, CaseIterable, bare lowercase cases
unlike CursorStyle these are never sent to ghostty, so the spellings are yours to choose
SettingsDecoder
four cases, each via init(rawValue:) like line 140's cursor read
a bad value falls back to its default independently and lands in invalidKeys; a misspelt key lands in unknownKeys
SettingsStore
add all four to defaultFileContents
SettingsStoreTests asserts the file names every key the decoder reads

Not settable: the footer height, the segment priorities, the marker vocabulary, the tier type scale, the icon. Those are the design; making them options would mean there was no design.

one validation rule

focusStyle == .invert forces attentionStyle == .quiet. Both fill the footer, and a bar that is filled for two reasons carries neither. Not an init — this type deliberately has none. Resolve it on read, the way Limits keeps its bounds next to the meaning:

public var resolvedAttentionStyle: AttentionStyle {
    self.focusStyle == .invert ? .quiet : attentionStyle
}

The stored value survives, so flipping focusStyle back restores the loud setting rather than silently having eaten it — and no view can reach the illegal pair, because no view reads the stored one.
